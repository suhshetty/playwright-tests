OTP code collisions this run: 7166. These are NOT a server fault. Odense issues a one-time login code stored per USER ACCOUNT, and each request replaces the previous one, so virtual users sharing a single test account overwrite each other's codes. With 150 peak VUs on one account, 734 of 14755 logins reached the content page (5.0%). A valid login measurement needs one account per VU; until then treat the login figures as a property of the test setup, not of Odense.

The two columns have different totals: 14755 login-page requests vs 8007 to GetTempCode. A failed login page ends the iteration before GetTempCode is called, so 6748 attempts never got that far. Login-page failures and OTP collisions are therefore SEPARATE and ADDITIVE causes of a low login success rate.

Caution when reading the latency figures above: requests that were refused return almost instantly, which pulls the percentiles DOWN. A low p95 alongside a high failure rate means most requests were rejected quickly, not served quickly.
